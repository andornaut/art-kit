## Scope

Short design summaries in `docs/design/<area>.md`, one work file per approved task in
`docs/work/<id>.md`, the convention in the [work-file README](README.md), and a CI split so
docs-only changes run only the attribution and lint checks.

## Criteria

- Each design area has a summary that links its topic docs and an index table of ID, title and link,
  with no status column.
- Work files are backfilled from 0.11.0 through 0.31.0 and the stock-check tooling.
- A first `changes` job classifies the changed paths. `lint` always runs; `verify` runs only when a
  path outside `docs/` changed or the diff cannot be classified.
- The AI attributions workflow is unchanged.

## Decisions

- The topic docs stay where they are and remain the detailed reference.
- Backfilled items with no recorded approval are labelled `inferred` (evident from the release) or
  `unrecorded`.
- Protocol work reference `ak-docs-rebuild`.

## Outcome

Delivered with the change that adds `docs/design/` and `docs/work/`; docs-only pushes run only lint and the attribution scan.
