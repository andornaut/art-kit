## Outcome

Apply the four public interface proposals raised during the structure refactor. Preserve every
existing export path and name, and keep encoded bytes, decoded RGBA and JSON output identical.

- Validation errors in `raster`, `glyphAtlas`, `bitmapFont`, `draw` and `compareRgba` use one
  consistent wording. Error text changes; error types stay the same (D6).
- Export a named return type for `buildBitmapFontFromGlyphs` (D5).
- Export `Point` and `Rect` from `build/rgbaImage` (D7).
- Render sprite-sheet frames through the shared raster frame code. Sprite-sheet PNG and JSON
  output stays identical; invalid-input error messages may change (D8).

## Result

- Validation errors in `raster`, `draw`, `compareRgba`, `glyphAtlas`, `bitmapFont` and `spriteSheet`
  read `<subject> must <constraint>`: the argument, option or input, then its constraint, with
  inclusive ranges as `min..max`. Error types and check order are unchanged.
- `build/glyphAtlas` exports `GlyphAtlas`, the existing return type of
  `buildBitmapFontFromGlyphs`, and `build/rgbaImage` exports `Point` and `Rect`. These are the
  only declaration changes.
- `spriteSheet` renders frames through `frameToRgba` and `composeSheet`; every sprite-sheet
  fixture passes unchanged with exact JSON and decoded RGBA.
