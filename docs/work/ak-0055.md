## Outcome

Apply the shared [source-structure policy](https://github.com/andornaut/game-coordinator/blob/main/docs/game-policies.md#source-structure)
(gc-0029) to the kit, with no public interface or output change.

- ESLint guards the area layers in `node/src`: `raster` imports no other area, `codecs` imports
  `raster`, `atlas` imports `raster` and `codecs`, `fonts` imports `raster`, and `build` imports
  no other area.
- `import-x/no-cycle` covers `scripts/` and the tests as well as `node/src`.
- TypeScript `erasableSyntaxOnly` is on; parameter properties, enums and namespaces use erasable
  forms.

## Result

- Each `node/src` area has its own `no-restricted-imports` list: the package boundary plus a
  pattern that rejects any `../` path into an area it may not import. The rule checks
  `import type` and re-exports too.
- `import-x/no-cycle` runs on `node/src`, `scripts/**/*.mts`, `tests/container/**/*.mts` and
  `node/tests/**/*.mjs`. The resolver maps a `.js` specifier to its `.ts` source, so cycles
  between source modules resolve; type-only imports still form no cycle. No cycle was found.
- `erasableSyntaxOnly` is on in `node/tsconfig.json`, the only tsconfig; Node runs scripts and
  tests by type stripping, which already rejects non-erasable syntax. The parameter properties
  of `Grid`, `BuildError` and `CheckError` are explicit fields with the same declarations,
  field order and emitted output.
